# DeepSeek CLI

Небольшой интерактивный клиент DeepSeek на Rust. Ответ печатается по мере
генерации, а история текущего диалога хранится только в памяти процесса.
Реплики пользователя и DeepSeek выделяются разными фоновыми полосами на всю
ширину терминала.

## Сборка

```bash
cargo build --release
```

Готовый исполняемый файл: `target/release/deepseek-cli`. При желании его можно
установить в Cargo bin-каталог:

```bash
cargo install --path .
```

## Настройка

Создайте локальный конфиг из примера:

```bash
cp deepseek.example.toml deepseek.toml
```

Вставьте API-ключ в `api_key`. Файл `deepseek.toml` исключён из Git, однако его
всё равно следует считать секретным и не пересылать другим людям.

Ключ также можно передать переменной окружения; она имеет приоритет над файлом:

```bash
DEEPSEEK_API_KEY='your-key' deepseek-cli
```

Доступные параметры:

```toml
api_key = "replace-with-your-key"
base_url = "https://api.deepseek.com"
model = "deepseek-v4-flash"
system_prompt = "You are a helpful assistant."
temperature = 1.0
max_tokens = 4096
timeout_seconds = 120
```

Кроме ключа, все поля необязательны и принимают показанные значения по
умолчанию. Другой файл можно выбрать явно:

```bash
deepseek-cli --config /path/to/config.toml
```

## Использование

```text
$ deepseek-cli
you> Объясни ownership в Rust одним абзацем
assistant> ...ответ появляется постепенно...
you> /exit
```

Команды:

- `/clear` — очистить историю текущего сеанса;
- `/exit` или `/quit` — выйти;
- Ctrl+D — выйти.

Если запрос оборвался или API вернул ошибку, незавершённая пара сообщений не
добавляется в историю.

Цвета автоматически отключаются при перенаправлении вывода. В интерактивном
терминале их можно отключить вручную стандартной переменной `NO_COLOR`:

```bash
NO_COLOR=1 deepseek-cli
```

## День 3: четыре способа решения в терминале

В ветке `Day-3` доступен интерфейс на [Ratatui](https://ratatui.rs/):
четыре панели 2×2, в каждой потоковый ответ на одну и ту же задачу.

```bash
cargo run -- --day3
```

Введи задачу после запуска и нажми Enter. F2 подставляет пример с известным
оптимумом (задача о рюкзаке), затем Enter запускает сравнение. Терминал должен
быть не меньше 90×28; для чтения удобно развернуть его на весь экран.

Четыре режима:

1. Только исходная задача, без system prompt и дополнительных инструкций.
2. Та же задача с инструкцией «Решай пошагово» и просьбой показать основные шаги
   и проверку результата.
3. Первый вызов API составляет промпт, второй действительно использует его
   вместе с исходными условиями. Сгенерированный промпт доступен по клавише `p`.
4. Один запрос с тремя ролями: аналитик, инженер и критик. Каждая роль должна
   дать решение, затем модель подводит общий итог. Это роли одной модели,
   а не независимые модели или агенты.

Всего пять запросов за запуск. Четыре метода выполняются параллельно, два
этапа третьего метода — последовательно. Истории независимы. Модель,
температура и бюджет токенов на вызов одинаковы и берутся из TOML.
По умолчанию системные промпты панелей пусты; их можно изменить через F3. По умолчанию для всех пяти вызовов
задан `thinking.type=disabled`: сравниваются инструкции в видимом ответе,
а не разные настройки скрытого рассуждения. Обычный CLI сохраняет прежние
настройки API.

Управление:

| Клавиша | Действие |
| --- | --- |
| Enter | Отправить введённую задачу |
| F2 | Подставить задачу-пример в режиме ввода |
| Ctrl+U / Backspace | Очистить ввод / удалить последний символ |
| Tab / Shift+Tab / 1–4 | Выбрать панель |
| ↑ / ↓ / PgUp / PgDn / Home / End | Прокрутить выбранный ответ |
| p | Показать промпт или решение в третьей панели |
| v | Изменить оценку выбранного ответа: не оценено, верно, частично, неверно |
| s | Сохранить текущие ответы и оценки в Markdown |
| n | Ввести следующую задачу после окончания текущего сравнения |
| q / Esc / Ctrl+C | Выйти (во время ввода: Esc или Ctrl+C) |

Ответы автоматически сохраняются после завершения всех методов в
`reports/day3-<timestamp>.md`. Если выставил оценки, нажми `s`, чтобы сохранить
новый отчёт с ними. Ошибка одного метода не мешает остальным; обрезанный по
лимиту ответ помечается ошибкой, а незавершённый сгенерированный промпт не
отправляется на второй этап. Выход отменяет незавершённые локальные запросы.

В каждой панели показаны время и количество слов. В третьем методе время
включает оба вызова, а количество слов относится к финальному решению.
Точность оценивается отдельно: сравни итог, выполнение условий и обоснование.
Приложение не объявляет самый длинный ответ лучшим и не выставляет оценку
через ненадёжное совпадение чисел в тексте.

Для встроенного примера точный ответ — B + C, вес 10 кг, ценность 48.
Единственность оптимума проверяется тестом с полным перебором 32 подмножеств.
Для своей задачи нужно самостоятельно определить эталон. Один прогон одной
задачи не устанавливает универсально лучший способ решения.

[Результаты реального прогона и разбор ошибок](docs/day3-results.md).

Токены берутся из `usage` API: входные (`prompt_tokens`), выходные
(`completion_tokens`) и общие (`total_tokens`). В третьей панели суммируются
**оба запроса** — создание промпта и решение по нему, включая повторную передачу
сгенерированного промпта на вход второго запроса. Счётчик `учтено 2/2 запросов`
означает полный итог; `1/2` — пока есть статистика только одного вызова.
Если API не прислал usage, показывается «нет данных API», а не ноль.
Эти же суммы сохраняются в Markdown. Старые отчёты без usage не пересчитываются
по числу слов.

## Сравнение температур

Ветка `codex/temperature-comparison` создана от сохранённого состояния `Day-3`.
Запуск четырёх панелей с одинаковым запросом и разными температурами:

```bash
cargo run -- --temperatures
```

Введи вопрос после запуска и нажми Enter. Панели:

1. `temperature = 0`
2. `temperature = 0.7`
3. `temperature = 1.2`
4. `temperature = 1.0` — дополнительный базовый вариант для четвёртой панели.

По умолчанию выполняются четыре независимых API-запроса, отличающиеся только `temperature`:
исходный текст, модель, лимит токенов и `thinking=disabled` одинаковы.
Дополнительные инструкции по способу решения и system prompt не отправляются.
Температура и остальные параметры берутся из отдельных конфигов панелей.

В каждой панели — ответ, время и фактические входные, выходные и общие токены
одного вызова API. Управление, прокрутка и выставление оценки такие же, как
в режиме дня 3; клавиша `p` здесь не используется. F3 открывает настройки выбранной панели. Отчёт сохраняется
автоматически в `reports/temperatures-<timestamp>.md`.

Режим `--day3` по-прежнему доступен для сравнения способов решения.
Одновременно `--day3` и `--temperatures` передавать нельзя.

### Отдельный конфиг каждой панели

При первом запуске создаются четыре независимых файла:

```text
panels/window-1.toml
panels/window-2.toml
panels/window-3.toml
panels/window-4.toml
```

Они используются в обоих режимах: `--temperatures` и `--day3`.
Кнопка **[F3 Настройки]** открывает конфиг именно этой панели.
С клавиатуры — выбери панель через Tab/1–4 и нажми F3; до отправки
первого запроса можно сразу нажать кнопку нужной панели мышью.

Доступны все поддерживаемые клиентом настройки:

| Поле | Значение |
| --- | --- |
| temperature | 0–2 |
| model | Имя модели на выбранном API |
| base_url | Адрес API до `/chat/completions`, например `https://host/v1` |
| api_key | Собственный ключ этой панели, в редакторе скрыт |
| system_prompt | Произвольный многострочный текст; пусто — без system message |
| max_tokens | Положительный лимит выходных токенов |
| timeout_seconds | Положительный таймаут запроса в секундах |
| top_p | 0–1; пусто в редакторе — не отправлять |
| stop | JSON-массив в редакторе, например `["Готово"]`; `[]` — отключить |
| thinking | `enabled`, `disabled` или пусто — не отправлять параметр |
| include_usage | `true` или `false`: отправлять ли `stream_options.include_usage` |

В редакторе Tab/↑↓ выбирают поле, Ctrl+U очищает значение, Backspace удаляет
последний символ. Можно вводить или вставлять текст; Ctrl+J добавляет новую
строку в system prompt. Enter, Ctrl+S или «Сохранить» сохраняют только выбранный
файл; Esc или «Отмена» закрывают редактор без изменений.

Параметры применяются к следующему запросу. Пока ответы генерируются,
редактирование заблокировано. Уже полученные ответы и отчёт сохраняют снимок
старых параметров. Каждый запрос использует system prompt своей панели;
в режиме двойного промпта он передаётся на обоих этапах.

При создании отсутствующего файла модель, адрес и ключ копируются из основного
конфига; system prompt изначально пуст, thinking — disabled. Существующие
файлы не перезаписываются. Если сохранился старый `windows.toml`, его температуры
переносятся при создании недостающих файлов в стандартной папке `panels`.
После создания панелей основная переменная `DEEPSEEK_API_KEY` **не переопределяет**
их собственные ключи: каждый файл независим.

Файлы `panels/*.toml` исключены из Git, на macOS/Linux создаются с правами `0600`.
API-ключи не записываются в отчёт. Примеры без секретов — в `panels.example/`.
Другую папку можно выбрать так:

```bash
cargo run -- --temperatures --panels-dir my-panels
```

Также работает `--windows-config my-panels`; теперь этот аргумент принимает
**каталог**, а не прежний общий TOML-файл. Для загрузки ручных правок перезапусти
программу. Ошибки полей и сохранения не заменяют работающую конфигурацию.

Подмена API поддерживает **совместимый Chat Completions API с SSE** и Bearer-ключом.
Для стороннего сервера можно оставить `thinking` пустым и отключить
`include_usage`, если он не поддерживает эти расширения. Другая схема API,
например Messages API, требует отдельного адаптера. Поддержка конкретных
параметров зависит от выбранного сервера и модели.


## День 5: сравнение моделей

```bash
cargo run -- --models --panels-dir panels-day5
```

Введи один вопрос и нажми Enter, либо F2 для задачи с эталоном.
Все включённые панели получают одинаковый вопрос без дополнительных инструкций
о способе решения. System prompt и параметры берутся из каждой панели.
Для честного сравнения сохраняй их одинаковыми, меняя только модель и тарифы.

В каждой панели показаны имя модели из конфига, время полного запроса в секундах,
входные, выходные и суммарные токены из API, оценка стоимости в USD.
Время включает сеть и получение полного потока; это не время до первого токена.
В двойном промпте по-прежнему суммируются токены обоих вызовов.
Отчёт с ответами, метриками и снимком настроек сохраняется в `reports/models-*.md`.

Новые поля доступны через F3:

| Поле | Значение |
| --- | --- |
| enabled | `false` отключает запрос панели |
| input_usd_per_million | USD за миллион входных токенов; пусто — неизвестно |
| output_usd_per_million | USD за миллион выходных токенов; пусто — неизвестно |

Стоимость = (вход × тариф входа + выход × тариф выхода) / 1 000 000.
Это оценка по полученным данным usage, без скидок за кэш. Если usage отсутствует
или поток оборвался до его получения, стоимость неизвестна. При частичном usage
оценка относится только к учтённым вызовам, как указано в строке токенов.
Нулевые тарифы можно явно задать для бесплатного API. Тарифы не обновляются
автоматически; при смене модели нужно поменять и их.

Примеры `panels-day5.example/` настроены на Flash, Flash Vision Exp и Pro;
четвёртая панель отключена. Локальный `panels-day5/` исключён из Git.
В примерах указаны пиковые тарифы DeepSeek на 7 сентября 2026:
Flash/Vision — $0.44 вход, $1.32 выход; Pro — $1.32 вход, $3.96 выход за миллион.
Это консервативная оценка: вне пиковых часов тарифы вдвое ниже, кэш также дешевле.
Пиковые интервалы: 01:00–04:00 и 06:00–10:00 UTC.
Источник: [официальные тарифы DeepSeek](https://api-docs.deepseek.com/quick_start/pricing/).

Flash Vision не является отдельным «средним» уровнем на текстовых задачах:
[DeepSeek описывает её текстовые способности как сопоставимые с Flash](https://api-docs.deepseek.com/updates/).
Этот набор сравнивает три доступных модели, но для строгого эксперимента
«слабая / средняя / сильная» потребуется другой набор моделей или провайдер.
Порядок в списке Hugging Face сам по себе не определяет качество модели.
